The daemon keeps compiler cache pipelines and maintenance
state warm across invocations. The local engine can still use the cache when
compiler delegation is unavailable.

## Responsibilities

- Run concurrent cache pipelines for delegated compiler invocations.
- Store completed C/C++ compiles handed over by wrappers.
- Run garbage collection at startup and every six hours, including `[cache.volumes]` shards. When the store is over its size limit, also sweep after a wrapper reports it.
- Flush entries that were stored without an fsync, every two seconds.
- At the start of a build, copy large executables next to the paths their restore will write, so the restore only renames the copy into place.
- When the machine is quiet, heal the blob index and compact `index.db`.
- When the machine is quiet, at most once an hour, remove tracked target directories whose workspace was deleted, and build units no build has used for 30 days. See [Target directory cleanup](/docs/getting-started/configuration#target-directory-cleanup).
- While the machine is idle, replace target files that are full copies of stored blobs with clones of those blobs.
- Copy another checkout's registry and git dependency units into a new target directory before Cargo checks it. See [New checkouts](/docs/getting-started/configuration#new-checkouts).
- Track running compiles for `kache monitor`.
- On macOS, exclude the cache directory from Spotlight and Time Machine.
- Exit when its config file changes, so the next start loads the new settings.

For delegated compiles, the daemon's pipeline already owns publication. A local
C/C++ engine can also hand its private output snapshots to the daemon when
`cache.daemon_publish` is enabled (the default). If the daemon cannot accept that
handoff within 25 ms, the engine publishes locally. Local execution using a
`[cache.volumes]` shard publishes from the engine.

Report JSON marks daemon-owned publication with `store_handed_off`. Queued
publication records its background time in `daemon_store_ms`, separately from
`store_ms`. A delegated pipeline that stores directly has no queued background
time. A daemon crash can lose queued cache entries; the compiler outputs remain
available to the build.

## When it is required

Caching works with no daemon. Delegated compilation and background maintenance
need it. If delegation is unavailable before Commit, the engine continues with the
local store. After Commit, a lost daemon connection fails the invocation; see
[Architecture](/docs/how-it-works/architecture).

## Endpoint placement

The runtime directory defaults to the cache directory. The default socket is `<runtime_dir>/daemon.sock`. Move the runtime directory with `[cache] runtime_dir` or `KACHE_RUNTIME_DIR`, or only the endpoint with an absolute `KACHE_SOCKET_PATH`. `KACHE_SOCKET_PATH` has no config-file key, and a relative or unusable value is ignored with a warning.

The daemon also binds a lifecycle control endpoint next to the socket: the socket path with its extension replaced by `.ctl`. With the default `daemon.sock` it is one byte shorter than the socket. A custom `KACHE_SOCKET_PATH` without an extension gets a longer one.

Use a short, user-owned runtime directory. Unix socket paths are limited to 103 bytes on macOS and 107 on Linux. `kache daemon start` checks both endpoint paths against that limit and refuses to start a daemon when either is too long. Shared temporary directories also allow another local user to interfere with adjacent lock and state files.

Every client and daemon process must resolve the same runtime and socket settings. Installed services do not inherit later shell exports; put persistent values in the config or service definition.

## Basic commands

```bash
kache daemon start
kache daemon status
kache daemon log
kache daemon stop
```

Bare `kache daemon` is an alias for `kache daemon status`. The status lists the CLI and daemon versions, whether the login service is installed, and where the socket, logs and startup errors are.

See [Lifecycle](/docs/daemon/lifecycle) for service installation and restart behavior.
